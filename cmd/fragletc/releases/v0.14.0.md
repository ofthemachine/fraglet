# fragletc v0.14.0

## Key Highlights
- **`#: secret=NAME:d=…`**: a tool declares the credentials it needs. The value comes from the caller's env var `NAME` and reaches the program only as the read-only file `$NAME_FILE` (`/run/fraglet/secrets/NAME`). It never appears in the docker command line, `docker inspect`, the container's environment, a host file, or the receipt.

## What's New

### `#: secret=` — declared secrets, delivered as files

```
#: secret=HA_TOKEN:d=Home Assistant long-lived access token
token = open(os.environ["HA_TOKEN_FILE"]).read().strip()
```

```
$ export HA_TOKEN=…            # or: op run -- ./ha-state.py …
$ ./ha-state.py -p entity=light.kitchen
```

- **One secret per header line.** `NAME` is `[A-Z][A-Z0-9_]*` and doesn't start with `FRAGLET_`. There are no source or transport options; wrap the call in `op run`, `security find-generic-password` and so on to pull from a vault.
- **Delivery works the way Docker Compose delivers environment-sourced secrets.** The container is created with `--rm`, `docker cp -` streams an in-memory tar that puts a 0444 file at `/run/fraglet/secrets/NAME`, and then `docker start -a` runs it. Stdin, exit codes and output behave exactly as with `docker run`. Tools that declare no secrets still take the single `docker run` path.
- **Interrupts are cleaned up.** SIGINT or SIGTERM force-removes the container, and with it the secret file.
- **Missing secrets fail early.** A missing or empty secret exits 2 before any container starts, listing what to set. `-e NAME` (or `-e NAME_FILE`) for a declared secret is refused, because it would put the value back into the environment.
- **Receipts are unchanged.** The declarations are part of the script, so `procedure_hash` covers them, the run stays conformant, and it keeps its memo key. The value is never recorded or fingerprinted.
- **`--fraglet-help` lists a tool's secrets.**
- **New lint rules:**
  - errors: `secret-name`, `secret-duplicate`, `secret-param-collision`
  - warnings (errors under `--strict`): `secret-no-description`, `secret-unused`

### Library
- `fraglet.SecretDecl` (`ContainerPath()`, `FileEnv()`), `fraglet.ParseSecretDecls`, `fraglet.ValidSecretName`, `fraglet.SecretMountDir`.
- `runner.Secret{Path, Value}` and `runner.RunSpec.Secrets`. The docker runner uses create → cp → start when secrets are present; the local runner refuses them.

## Compatibility
- No entrypoint or image changes: secrets need only the new fragletc.
- Existing headers and receipts are unchanged. `secret=` was a reserved token and is now a directive.
- `-e NAME=value` still behaves as before (it forwards the value in the docker command line). Use `#: secret=` for credentials.
