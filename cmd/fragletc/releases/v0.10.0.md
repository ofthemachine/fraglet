# fragletc v0.10.0

## Key Highlights
- **`#: network=none` is now enforced** — declaring it in the script header makes `fragletc` launch Docker with `--network none`, cutting all egress at the container boundary.
- **`--network` CLI flag** — explicit override (`none`, `bridge`, `host`, …). An explicit flag always wins over the header.

## What's New

### Header-driven network isolation

A fraglet that is pure computation can now *prove* it:

```python
#!/usr/bin/env -S fragletc --image ofthemachine/python3@sha256:...
#: d=The Nth Fibonacci number. Pure computation, no network.
#: network=none
#: param=n:required
```

When the header declares `network=none` and the caller does not pass `--network`, `fragletc` adds `--network none` to `docker run`. The container has loopback only — no `eth0`, no outbound sockets.

```bash
$ ./fibonacci.py -p n=10          # isolated automatically
$ fragletc --network none ./fibonacci.py -p n=10   # same, explicit
```

### `--network` flag

```bash
fragletc --network none ./tool.py -p n=17
fragletc --network bridge ./tool.py -p n=17   # overrides #: network=none
```

Omitted, the flag is empty: `network=none` in the header isolates; anything else leaves Docker on its default bridge.

`#: network=required` is a declaration for callers and catalogs — this result depends on live network state and must not be memoized indefinitely. It does not change Docker networking. The container keeps the default bridge so egress succeeds.

### Why This Matters

Previously `network=` was documentation only. A tool that claimed to be hermetic still got a fully networked container. Isolation is now a host-side property of the run, not a promise the script makes about itself.

Library callers (`engine.Run` / `engine.Execute`) get the same resolution: an explicit `NetworkMode` wins; otherwise `#: network=none` defaults the run to `"none"`.

## Semantics

- **Explicit `--network` always wins** over the header.
- **`network=none`** → Docker `--network none`.
- **Anything else** (`network=required`, no declaration, empty flag) → omit `--network`, Docker default bridge.

## Reproducible Builds

To verify a release binary was built from the claimed source:

```bash
./verify-release.sh fragletc-v0.10.0
```

This runs the build inside a `golang:<version>-bookworm` container pinned to the exact Go version from `go.mod`, downloads the release's `build-info.json`, builds all platform binaries, and outputs sha256 checksums. Compare against `checksums.txt` from the release.
