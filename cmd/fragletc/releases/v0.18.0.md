# fragletc v0.18.0

## Key Highlights
- **Dynamic defaults resolve here**: a param declared `default=@hour` (or `@year`, `@month`, `@day`, `@minute`, `@iso`, `@epoch_ms`) reaches the container as the hour, not the text `@hour`, and the receipt records the value.
- **The window is the cache's scope**: the resolved value is a param like any other, so it is in the run's memo key. `default=@hour` means one result per hour, `@day` one per day.

## What's New

### Dynamic defaults

A tool declares how fresh its answer must be beside the code that fetches it:

```
#: param=call_time:default=@hour
```

fragletc resolves the token against the run's instant, in UTC, truncated to the token's granularity (`@hour` → `2026-10-24T05`, `@day` → `2026-10-24`). The vocabulary is closed: no arithmetic, no format strings, and an unknown `@token` is refused. An explicit `-p call_time=…` still wins.

Every default of one run is resolved against one reading of the clock (`engine.RunOptions.Now`; zero is the clock), so a chain that straddles an hour boundary never buckets its steps into different hours. `fraglet.ResolveDefault(raw, now)` is exported for callers that resolve before running (operon's invoke and solve fold through it).

### Upgrading

A tool that relied on receiving the literal text `@hour` now receives the hour. Pass `-p name=@hour` explicitly to keep the old value.
