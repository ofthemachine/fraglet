# fragletc v0.20.0

## Key Highlights
- **`#: run=`: a script says how it runs**, so a fraglet no longer needs an image built with the fraglet entrypoint. With its image pinned by digest in the shebang, the file is everything needed to run it: its hash names the script, the image and the command together.

## What's New

### `#: run=<program> … {code:<path>}`

```
#!/usr/bin/env -S fragletc --image golang:1.25@sha256:<digest>
#: run=go run {code:/work/main.go}
package main
…
```

The body is written to the path `{code:<path>}` names and the command runs in place of the image's entrypoint. The path is always given (absolute, exactly once, never the first word): fragletc chooses nothing, so no run depends on a default. Words split on white space and are never quoted; a command that needs a shell names one (`run=sh {code:/work/run.sh}`).

Params reach the script under their bare names (`#: param=city` → `$CITY`), secrets as files (`$NAME_FILE`), outputs under `/output`, and stdin as declared: as in any fraglet. Everything on a run line is its command, so none of its words is read as another directive. `fragletc lint` checks the line (`run-value`).

A script with a run line names its own program, so it runs only in a container: where Docker is unavailable it is refused, never run on the host.

### Library

`fraglet.ParseRun`, `fraglet.RunRecipe`, `fraglet.BareEnv`, `runner.DockerAvailable`. `engine.Execute` and `engine.Run` honour the line.
