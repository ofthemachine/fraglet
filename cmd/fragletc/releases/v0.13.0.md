# fragletc v0.13.0

## Key Highlights
- **`--receipt` / `FRAGLETC_RECEIPT_DIR`** — a JSON record of one run in which every input and output is referenced by its content hash: the invocation (procedure hash, image digest, params, inputs, argv, `-e` names, stdin mode), the outcome (exit code, stdout digest, every output hash), and a memo key that identifies the computation, present exactly when nothing reached the container outside the declared parameters.
- **`#: stdin=`** — stdin is a declared input like any other. A piped stdin is buffered by default (read to EOF, hashed, forwarded); `stream` is the explicit opt-in for interactive programs; `none` asserts the program does not read it.
- **`#: when=`** — a tool-level trigger clause (*when* an agent should reach for the tool), with a `when-missing` lint.

## What's New

### `--receipt path` and `FRAGLETC_RECEIPT_DIR`

```
$ FRAGLETC_RECEIPT_DIR=~/r ./tools/math/is-prime.py -p n=7
Prime: yes
fragletc: receipt -> ~/r/20260914T060659Z-is-prime-bc42b50d6ee4.json
```

`--receipt <path>` is preprocessed like `-p` and `--output`, so it works after the script name in a shebang invocation. Without it, `FRAGLETC_RECEIPT_DIR=<dir>` saves every run's receipt there, named `<started>-<script>-<memo key prefix>.json` (`-unkeyed` when the run has no key). Unset, receipts are computed but not saved — there is deliberately no default directory.

```json
{
  "schema": "fraglet-receipt/2", "fragletc": "v0.13.0", "procedure": "tools/math/is-prime.py",
  "procedure_hash": "sha256:…", "image": "ofthemachine/python3@sha256:…", "image_digest": "sha256:…",
  "network": "none", "stdin_mode": "buffer",
  "params": { "n": "7" }, "inputs": { "": "sha256:e3b0…" }, "argv": [], "env": [],
  "memo_key": "sha256:…",
  "started": "…", "finished": "…", "exit_code": 0,
  "stdout": { "hash": "sha256:…", "bytes": 11 }, "outputs": { "": "sha256:…" }
}
```

- The first block is the **invocation**: everything that reached the container. `procedure_hash` is sha256 of the whole script file, shebang included, so a pinned image digest is part of the identity. `params` are declared scalars by alias with defaults folded; `inputs` are content hashes — `""` for stdin, `<alias>` for each `:file` param. `argv` are undeclared positional arguments; `env` are `-e` variable *names* (values are never recorded or fingerprinted — `-e` is how secrets reach a tool). `image`/`network`/`mode` are the effective values, so a CLI override of the shebang is visible.
- `memo_key` is a documented formula over `procedure_hash`, `params` and `inputs` — merge the two maps, sort keys, render each as `lower(key):value`, sha256 over `procedure_hash + "\n" + "\n" + join("\n") + "\n"` — and is present **only for a conformant invocation**: `argv` and `env` empty, stdin recorded. `pkg/receipt`'s tests pin the formula to known-answer vectors, so anyone holding a receipt can recompute its key from its fields. A stream run, or a run with args or `-e`, is receipted like any other, without a key.
- The second block is the **outcome**. `outputs[""]` is stdout when the script declares no `output=`; otherwise every file under `/output` by relpath, hashed from fragletc's own scratch mount so a failed `--output` copy cannot hide a file. `stdout` is recorded either way.
- Execution class is not stored: it is a predicate over the invocation (`receipt.Invocation.Class()` — hermetic iff conformant, `network=none`, and an `@sha256`-pinned image). `schema` is the receipt's only version field.

In the Open Knowledge Format's terms (SPEC.md §10, Attested Computations) a fraglet is an attested computation and the receipt is the executor's evidence: the invocation block is the expanded artifact an attester compares against the sanctioned script and its declared parameters.

### `#: stdin=` — stdin is a declared input

| Header | fragletc does | Receipt |
|---|---|---|
| *(none)* or `#: stdin=buffer` | reads a piped stdin to EOF, hashes it, forwards it; a terminal is never attached | `inputs[""]` = hash of what was piped |
| `#: stdin=stream` | live passthrough for interactive programs | no `inputs[""]`, no `memo_key` |
| `#: stdin=none` | attaches nothing, even when piped | `inputs[""]` = empty hash |

A run waits on an open pipe the way any program reading stdin does; that is the contract. `--stdin=<mode>` overrides the header for one run, is preprocessed so it works in any position before `--`, and is validated before anything runs. Lint: `stdin-value` (error) rejects any other mode.

### `#: when=` — the trigger clause

`d=` describes what a tool does. `when=` describes the situations it is for, in the words a request would use:

```
#: d=Real current conditions for any city, via wttr.in's compact one-line format.
#: when=Use when the user asks what the weather is like right now somewhere, or a caption or notification needs a live conditions phrase.
```

Agent-skill catalogs publish `d=` as the skill description and the spec wants that to include a trigger clause; without `when=` a catalog had to invent one that carried no matchable keywords. Multiple `when=` lines join with a space; `--fraglet-help` prints it as `When: …`; `fragletc lint` reports `when-missing` as a warning (error under `--strict`) beside `desc-missing` and `network-missing`.

### Library
- `pkg/receipt`: `Invocation` (with `MemoKey()`, `Unbound()`, `Class()`), `Outcome`, `Receipt`, `Build`, `ProcedureHash`, `Digest`, `Hasher`, `AnonKey`. Stdlib-only.
- `engine.RunWithReport` returns `RunReport{receipt.Invocation; receipt.Outcome}`; `engine.Run` is unchanged. `RunOptions.StdinMode` overrides the header (empty = header, undeclared = buffer).
- `fraglet.ParseStdin`, `fraglet.StdinNone/StdinBuffer/StdinStream`, `fraglet.ParseMetaWhen`.

## Compatibility
- Piped stdin behaves as before (forwarded), now hashed. Interactive programs that need a live stdin must declare `#: stdin=stream`.
- No entrypoint changes; containers are unaffected.
