# fragletc v0.7.0

## Key Highlights
- **`--output-dir <hostdir>`** — copy everything written to `/output` into a host directory after the run, for wrapping a CLI tool whose output filename is only known at runtime. No `output=` declaration required. Mutually exclusive with `--output`.
- **`--output <dest>` shorthand** — when a fraglet declares exactly one `output=`, `--output <dest>` alone is enough; no need to repeat the fraglet's own declared filename back to it.

## What's New

### `--output-dir`

Some fraglets wrap a real CLI tool that names its own output file — an explicit `-o` flag the caller passes through, or the tool's own default naming. There's no fixed `relpath` to declare in that case, so the existing `output=` + `--output` contract doesn't fit.

```bash
fragletc --vein=python --output-dir=./out dynamic_name.py custom-name.txt
```

The container writes into fragletc's own scratch mount at `/output`; after the run, everything there is copied into `./out`, overwriting same-named files — no declaration or validation of specific filenames needed. Because `--output-dir` already copies everything out, it's mutually exclusive with `--output`.

### `--output <dest>` shorthand

Previously, copying out a declared output required repeating its exact declared name:

```bash
fragletc --output meme.png=my-photo.png render_meme.py
```

When a fraglet declares exactly one `output=`, there's nothing to disambiguate, so the relpath can now be omitted:

```bash
fragletc --output my-photo.png render_meme.py
```

A bare token that already matches a declared relpath, or an explicit `relpath=dest` that doesn't match, is left alone — the shorthand only kicks in for the genuinely unambiguous case; a mismatched explicit relpath still surfaces the normal "not declared" error rather than being silently reinterpreted.

## Reproducible Builds

To verify a release binary was built from the claimed source:

```bash
./verify-release.sh fragletc-v0.7.0
```

This runs the build inside a `golang:<version>-bookworm` container pinned to the exact Go version from `go.mod`, downloads the release's `build-info.json`, builds all platform binaries, and outputs sha256 checksums. Compare against `checksums.txt` from the release.
