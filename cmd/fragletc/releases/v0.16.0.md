# fragletc v0.16.0

## Key Highlights
- **`fragletc lint` reads the shebang** as fragletc will: an unknown flag, a value flag with no value, a stray word that would be taken for the script, a missing `env -S`, and an image not pinned by digest are all caught before a run misbehaves.

## What's New

### `fragletc lint`: shebang rules

A fraglet runs through its shebang, and a mistake there surfaces only at run time, often as fragletc reading a flag's value as the script. Lint now checks the first line of any script whose shebang invokes fragletc:

| Rule | Level | Catches |
|---|---|---|
| `shebang-env-split` | error | arguments without `#!/usr/bin/env -S fragletc …` (Linux passes a shebang's arguments as one word) |
| `shebang-flag` | error | a flag fragletc does not have |
| `shebang-flag-value` | error | a flag that takes a value (`-v`, `--image`, …) followed by another flag or nothing |
| `shebang-positional` | error | a word after the flags, which fragletc would read as the script |
| `shebang-image-unpinned` | warning | `--image` naming a tag rather than `name@sha256:…`, so a later run may differ |

```
#!/usr/bin/env -S fragletc --image python:3.12 --bogus x -v --mode main
```
```
x.py:1: error: shebang-flag: fragletc has no flag --bogus a shebang can carry (fragletc --help lists them)
x.py:1: error: shebang-flag-value: -v takes a value, but is followed by --mode (e.g. -v python, or --image name@sha256:…)
x.py:1: warning: shebang-image-unpinned: image python:3.12 is not pinned: a tag can move, so the same script may run differently later; pin it as name@sha256:…
```

### Library

- `pkg/fraglet`: `Lint` includes the shebang rules.
