# fragletc v0.11.0

## Key Highlights
- **`default=` is injected** — omitting `-p` materializes the declared default into the container env. Explicit `-p` (including empty) always wins.
- **Param `description=` / `d=`** — per-parameter prose in `--fraglet-help` (and missing-required listings). Must be the last modifier; spaces are allowed.

## What's New

### Defaults are transport, not documentation

```python
#: param=encoding:default=cl100k_base
```

```bash
$ ./tool.py                    # ENCODING=cl100k_base inside the container
$ ./tool.py -p encoding=o200k_base   # override
$ ./tool.py -p encoding=             # explicit empty; default is NOT applied
```

The header is the single source of truth. Script bodies no longer need `os.environ.get("ENCODING", "cl100k_base")` fallbacks for declared defaults.

### Param descriptions

```python
#: param=settle_ms:default=2000:description=Extra wait after page load
#: param=url:required:d=Target page URL
```

```
Parameters for ./tool.py:
  settle_ms    (optional, default: 2000) — Extra wait after page load
  url          (required) — Target page URL
```

`description=` / `d=` must be last on the token so the value may contain spaces and colons. Multiple `param=` on one line still split on `" param="`.

## Upgrade Notes
- Callers that relied on "omit `-p` ⇒ unset env" for a param that also has `default=` will now see the default value. Prefer an explicit empty `-p alias=` if unset-vs-default matters.
- Catalog/skill docs that claimed `default=` was help-only are obsolete as of this release.
